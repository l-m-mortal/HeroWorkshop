# Промпт для продолжения работы локально (Hero Workshop / DotA HQ-мод)

Скопируй этот файл целиком в первое сообщение новой сессии Claude Code, запущенной
на Mac из папки репозитория. Всё, что ниже, написано для модели.

---

Ты продолжаешь долгую работу над модом для DotA 6.85ne14 под Warcraft III 1.31.1 (macOS).
Цель проекта: перенести в карту 6.85 внешний вид мода «Dota HQ V5» (эталон: карта DotA 6.77b
с этим модом под 1.26a) и добавить удобства в духе Dota 2 (иконки, кулдауны, окно магазина).
Предыдущая сессия шла в облаке без доступа к игре, поэтому всё проверялось пользователем
вручную по скриншотам. Теперь ты работаешь локально: у тебя есть папка игры, можно самому
запускать `python3 map_fix.py ...`, смотреть файлы паков и проверять результат в игре
(запуск матча делает пользователь, ты просишь скриншот).

## Как общаться и работать

* Пользователь пишет по-русски, отвечай по-русски, коротко, без лишних вопросов; если
  вопрос нужен, задай один и предложи вариант по умолчанию.
* Рутинные задачи (поиск файлов, разбор паков, вспомогательные скрипты) делегируй
  субагентам на более дешёвой модели, сам держи решения и проверку.
* Каждая правка карты только через `map_fix.py <команда> --apply` (без `--apply` команда
  печатает план). Карта бэкапится автоматически (`Dota Mod Project/Archives/HeroWorkshop/Backups`).
* Папка `state/` локальная, в git не входит: там `state/<карта>/state.json` с историей
  правок (иконки, масштабы, `doodads_added`, `custom_doodads_added`, `removed_placements`,
  `model_lift`, `model_shift`, `cliffs`). Не удалять.
* **Обновляй `docs/HANDOFF.md` после каждого законченного шага** (это требование пользователя),
  коммить и пушь в ветку `claude/optimistic-gauss-alg516`.
* Пользователь любит получать готовые команды zsh целиком, чтобы скопировать и запустить.

## Окружение

* Игра: `Warcraft III/` (1.31.1, macOS). Рабочая карта: `Maps/Downloads/Dota_Radiant_Terrain_Fix_v4.w3x`.
  Эталон: `Dota Mod Project/Sources/Maps/DotA v6.77b.w3x` (и пак `Dota Mod Project/Sources/Packs/DOTA 2 mod/DOTA-HQv5_RePack.part01/...`).
* Репозиторий: `Dota Mod Project/Tools/HeroWorkshop` (этот), ветка `claude/optimistic-gauss-alg516`.
  Конфиг: `workshop.local.json` (game_root, map, backups). Запуск: `python3 map_fix.py <fix> [--apply]`,
  `python3 workshop.py ...`, `zsh *.sh`. Инструменты: `python3 map_fix.py list`.
* Файлы мода рядом с игрой: `WC3DotaHQTest/A/...` (HQ-мод, структура = пути игры),
  `WC3Dota2Test/...`, `WC3WardotaTest/...`. **Loose-файлы на диске имеют приоритет над файлами
  внутри карты**, поэтому модели из этих папок правятся на диске (`model-events --into root`,
  оригинал остаётся как `.hw_orig`), а стандартные пути кладутся в карту.
* SwiftUI-приложение `HeroWorkshopUI` (запуск `Open Hero Workshop.command`) вызывает `workshop.py`.
* Библиотека иконок: `Dota Mod Project/Library/icons/`; пользовательские PNG:
  `Library/icons/custom/<kind>/<id>/` (`workshop.py add-icon КЛЮЧ файл.png`, в UI пункт
  контекстного меню ячейки «Добавить PNG в библиотеку»).

## Открытые задачи (по приоритету), где остановились

1. **Склоны: проверить разводку по берегам реки.** Пользователь должен был запустить
   `python3 map_fix.py cliffs --split --apply` после `git pull` и прислать скриншоты
   (у реки на стороне Dire раньше были склоны с текстурой Radiant). Если где-то сторона
   определена неверно, правится функция `side_of` в `fix_cliffs` (`map_fix.py`): река = самая
   большая связная область клеток с флагом воды (byte4 >> 4 & 4 в war3map.w3e), клетка
   сравнивается по i+j с ближайшей клеткой реки. Затем пользователь хочет **подобрать
   текстуры склонов из другого пака** (текущие HQ коричневые, ему не нравятся):
   `cliffs --scan` печатает все текстуры склонов/земли и CliffTypes.slk в HQ-папке, паках и
   Build; выбранные файлы ставятся `cliffs --radiant ФАЙЛ --dire ФАЙЛ --apply` (png/blp).
   Идея: Radiant в тон травы (Ashenvale-подобная), Dire в тон тёмной земли (Northrend).
2. **Деревья из HQ-пака не появляются.** `trees --apply` кладёт в карту
   `Doodads\Terrain\AshenTree\AshenTree0-4.mdx` (+D,S) и `ReplaceableTextures\AshenvaleTree\AshenTree.blp`
   из `WC3DotaHQTest/A`. Лес Radiant = тип `ATtr` (варианты 0-4, путь в w3b не переопределён,
   только тон 190 и масштаб 1.1), Dire = `NTtw` (варианты 0-9, `--which northrend`).
   HQ-модель использует replaceable-текстуру 32. Нужно: запустить команду локально, убедиться,
   что напечатала «Записано в карту» (проверить `python3 map_fix.py dump` и наличие файлов
   в карте), перезапустить матч. Если модели в карте есть, а деревья прежние, проверить,
   не лежит ли на диске loose-файл с тем же путём и версию MDX (800). См. `docs/AUDIT_ranged_and_trees.md`.
3. **Стена вокруг фонтана Radiant утоплена.** У фонтана нет частей сборки AshenRock7; там
   `AOnt` (2), `CPct` (1), `D009`, `AObd`, `NOfp` (`probe --at=-7168,-7168,900`).
   `zsh props.sh 150 Ashenvale/Props` (все HQ-модели Ashenvale/Props) стену не поднял. Сейчас
   Ashenvale/Props могут стоять на +150: **сначала `zsh props.sh 0 Ashenvale/Props`**.
   Дальше: выяснить модель стены (типы из `probe`, затем `hq-doodads --textures` по
   кандидатам; возможно `CPct`/`NOfp` из другой папки HQ) и поднять `model-shift --match <модель> --dz N`.
   Игра **игнорирует z размещения декораций** в war3map.doo (`doodads-z` бесполезен), двигать
   надо геометрию: `model-lift` (части сборки) или `model-shift` (модель целиком).
4. **Лишние лестницы у ямы Рошана** (перенесены из 6.77b): `remove --types ARrk --near=4208,-2288,1200`
   ничего не нашёл. Найти тип: `probe --at=4208,-2288,900`, затем `remove --ids ...`.
   Кандидаты: `YTlb`, `LObz`, `CObl` (см. `doodads_added` в state).
5. **Нумерация частей сборки AshenRock7**: пересчёт «часть -> место» ненадёжен, метки
   `labels.sh` встают не туда. Надёжно только `zsh parts_probe.sh DSxx ...` (часть на 800,
   новый матч, Enter). Известно: DS01/DS02 = плиты у выхода из базы Radiant вверх.
6. **Звук дальней атаки** (Снайпер `Usyl`, Дроу `Nbrn`), припарковано: в моделях
   Wardota/Dota2 нет звуковых событий. Снайпер: `model-events --path 'WC3WardotaTest\Units\Human\Rifleman\Rifleman.mdx' --events 'SNDxKRIF@370' --into root --apply`
   (не подтверждено). Дроу: звук шёл через `weapsd1` в UnitWeapons.slk. Коды звуков:
   `Build/DotaHQ/Inputs/NativeSoundInfo/animlookups.slk`.
7. **Потайные лавки**, припарковано: оставлены с моделью торговца. Идея: юнит = невидимый
   куст, шатёр отдельной декорацией с текстурой под сторону; модель шатра искать в
   `Dota Mod Project/Sources/Packs/` по `ShopKeeper`/`secretshop`.
8. **Магазин, хвосты** (пользователь делает сам): панель правее 0.8 обрезается (родитель
   GAME_UI; `--parent world` даёт полную ширину, кнопки там не проверены), кнопка SHOP высоковата.
9. Столбы с цепями у фонтана Dire родные, не трогать. Все части AshenRock7 на 0 — правильно.

## Важные факты про WC3 1.31, добытые опытом

* Кадры (frames) с родителем GAME_UI обрезаются при x > 0.8 (широкий экран);
  `ORIGIN_FRAME_WORLD_FRAME` даёт всю ширину. Клики по области панели команд до своих кнопок
  не доходят. `BlzFrameIsVisible`, `BlzGetAbilityId` в 1.31 отсутствуют (карта не грузится).
  TEXT-кадры по типу рисуются шрифтом по умолчанию.
* Модель без последовательностей (sequences) не рендерится; добавление Stand даёт дрожание.
* Разрезание модели на части (`split-model`) ломает карту, вместо него `model-lift`.
* JASS вставляется в `war3map.j` шаблоном: блок globals, функции перед main, `TimerStart` в main;
  проверка pjass. Доп. текст в `war3map.j` не должен содержать не-ASCII.
* Аргументы с минусом писать через `=`: `--near=-7168,-7168,900`. Скрипты запускать через `zsh`.
* После каждого моего пуша пользователь делает `git pull` перед запуском команд, иначе
  бегут старые версии.

## Команды-шпаргалка

```zsh
python3 map_fix.py list
python3 map_fix.py probe --at=X,Y,R             # декорации вокруг точки (здесь и в 6.77b)
python3 map_fix.py cliffs [--scan|--split|--radiant F --dire F|--ground|--undo] --apply
python3 map_fix.py trees [--which ashenvale|northrend|all] [--undo] --apply
python3 map_fix.py dump                         # .work/<карта>/dump.zip без моделей
zsh fix_scene.sh                                # вся сцена декораций разом
zsh stairs.sh N [all|radiant|dire|rad-wall|...|DS03]
zsh props.sh N [Ashenvale/Props|модель]
zsh parts_probe.sh DS02 DS03
python3 workshop.py add-icon item:I0B4 icon.png
```

Начни с того, что прочитаешь `docs/HANDOFF.md` (короткая актуальная сводка), запустишь
`git status`, `python3 map_fix.py cliffs` и `python3 map_fix.py trees` (без --apply) и
спросишь пользователя, с какой открытой задачи продолжать; по умолчанию предложи пункт 1.
