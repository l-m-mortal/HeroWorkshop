# Hero Workshop

Переносимый конвейер для основной карты `D85 06 DotaHQv5.w3x`: позволяет независимо
заменять иконки **существующих** способностей героя и задавать масштаб основной
и альтернативной моделей.
Он не меняет файлы самого Warcraft III.

Репозиторий не содержит карту и тяжёлые исходные паки. Карта выбирается через
`workshop.json`, локальный `workshop.local.json` или переменные окружения.
Выбранные PNG/BLP хранятся отдельно от JSON-конфигураций в `assets/icons/` —
эту папку можно безопасно коммитить и переносить вместе с кодом.

## Начало работы

Проще всего открыть Finder и дважды нажать `Open Hero Workshop.command`.
При первом запуске команда сама создаст игнорируемое Git окружение `.venv`,
установит зависимости из `requirements.txt` и соберёт Swift-приложение.
В приложении можно перетащить PNG или BLP в Enabled/Disabled: PNG показывается
сразу, а перед применением автоматически преобразуется в BLP1 64×64. Исходный
PNG остаётся в папке героя и не портится.

```zsh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
python3 workshop.py doctor
python3 workshop.py bootstrap
python3 workshop.py show Invoker
```

Если репозиторий лежит внутри текущего `Dota Mod Project/Tools`, карта Dota HQ
V5 обнаруживается автоматически. Для отдельного клона скопируйте
`workshop.local.example.json` в `workshop.local.json` и укажите локальный путь
к Warcraft или карте. Этот файл намеренно игнорируется Git. То же можно сделать
без файла:

```zsh
HERO_WORKSHOP_MAP="/полный/путь/D85 06 DotaHQv5.w3x" python3 workshop.py doctor
```

Поддерживаются также `HERO_WORKSHOP_GAME_ROOT`, `HERO_WORKSHOP_ICON_ROOT` и
`HERO_WORKSHOP_WORKSPACE`.

`bootstrap` читает данные именно из текущей карты и создаёт папки в `heroes/`.
Для каждой способности создаётся отдельная ячейка. Число ячеек определяется
`heroAbilList` и `abilList` юнита, поэтому у Invoker будут все реально
назначенные ему способности, а не искусственное ограничение в четыре.

## Иконки

Выбранные иконки находятся в
`assets/icons/heroes/<Hero__rawcode>/slots/NN_<abilityRawcode>/`:

* положите нужную PNG (предпочтительно) или BLP в `normal.png` / `normal.blp`;
* при наличии отдельной затемнённой версии положите её в `disabled.png` / `disabled.blp`;
* удалённый или отсутствующий файл означает «не менять этот слот».

Для предметов используется `assets/icons/items/`, для обычных юнитов —
`assets/icons/units/`. Старые `heroes/*/slots`, `items/*/slots` и
`units/*/slots` являются генерируемыми деревьями и не попадают в Git.

Для тестового UI в репозиторий также включён каталог командных иконок,
извлечённых из текущей карты `D85 06 DotaHQv5` и из сохранённых наборов:
`assets/icons/catalog/`. В `current-map/` лежат иконки текущей карты, а в
`sources/icon-audit/` — наборы `Dota_1_5`, `114_Heroes_Icons`, предметы и
`Shared_or_Unassigned`. В каждой коллекции сохранены BLP и PNG-превью.
Вкладка «Каталог иконок» показывает все PNG из этого дерева и указывает папку
источника. Каталог не подменяет привязки способностей: слоты конкретного героя
по-прежнему лежат в `heroes/` и заполняются отдельно.

HUD-ресурсы Dota HQ V5 сохранены отдельно в
`assets/icons/catalog/current-map/ui-assets/`: консольные панели, inventory и
command-button states, курсоры, minimap, HP/mana bars, cooldown и пассивные
кнопки. Вместе с ними сохранены MDX-файлы UI и исходник cooldown overlay в
`assets/icons/catalog/sources/ui-scripts/Cooldown.fdf`. Эти файлы предназначены
для последующей сборки/патчинга HUD и не смешиваются с ability/item icons.

HUD-ресурсы из тестовых карт также сохранены раздельно в
`assets/icons/catalog/sources/map-ui/`: `D85_03_Wardota2`,
`D85_04_SelectedMix`, `D85_05_WardotaDecor` и `D85_01_DotaHeroesV2`.
Так можно сравнивать варианты HUD, не теряя исходную принадлежность ассета.

Одна способность — одна ячейка. Если в текущей карте у героя действительно
только две способности, третья BLP не создаст новое заклинание: для этого
нужна отдельная игровая правка карты. Если же у Invoker, героя с Invoke или
другого героя есть шесть, десять либо больше назначенных способностей, для
каждой появится отдельная ячейка и их можно менять независимо.

У Invoker в этой версии карты стандартно назначены пять записей: три сферы,
Invoke и инвентарь. Заклинания, появляющиеся после Invoke, могут выдаваться
триггером в момент игры. Их rawcode нельзя надёжно угадать по `heroAbilList`:
после аудита добавьте его вручную в `extra_abilities` файла `hero.json`,
например `{"base_ability":"A123","source":"triggered"}`, и вновь запустите
`bootstrap`. Для него появится отдельная папка BLP. Такая запись не создаёт
новое заклинание: она описывает существующую способность, которой карта уже
пользуется.

## Масштаб

В приложении задайте множители основной и альтернативной модели отдельно.
`1.0` сохраняет исходный размер, `1.20` увеличивает выбранную модель на 20%,
`0.85` уменьшает её на 15%. Конвейер меняет только `unitUI.slk:modelScale`
(колонка X37); `unitUI.slk:scale` (X22), круг выбора и полоска здоровья не
меняются. Для героя без альтернативной модели второе значение игнорируется.

## Применение

```zsh
python3 workshop.py apply Invoker
python3 workshop.py apply all
```

Перед применением создаётся резервная копия в `Backups/HeroWorkshop/`.
Для активной иконки конвейер создаёт отдельную копию способности с собственным
rawcode и переназначает её только выбранному герою. Поэтому замена Coil у
Abaddon не меняет Death Coil у других юнитов, которые используют исходную
способность.

Трёхмерный портрет в нижней панели определяется MDX-моделью и portrait-camera,
а не BLP-иконкой. Этот конвейер меняет кнопочные иконки; модели и их портреты
остаются отдельной задачей.

## Что отправлять в Git

Коммитьте весь каталог HeroWorkshop. `.gitignore` исключает `.work`, резервные
копии карт, Swift `.build`, виртуальное окружение, локальные пути и сами W3X.
MPQ-утилиты в `tools/` маленькие и нужны для работы после клонирования на macOS,
поэтому они остаются в репозитории. Полный набор отслеживаемых исходников и
выбранных иконок занимает лишь несколько мегабайт; большая внешняя библиотека
`Dota Mod Project/Workspaces/Dota2/Icon Audit` в репозиторий не включается.

## Предметы

Во вкладке «Предметы» найдите предмет по названию или rawcode, положите PNG
или BLP в Enabled и при необходимости Disabled, затем нажмите «Применить в
карту». Конвейер создаёт отдельную копию назначенной предмету способности и
переназначает её только этому предмету. В Terminal доступна команда
`python3 workshop.py apply-item all`.
